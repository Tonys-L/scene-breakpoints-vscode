# 模型调度建议规则

本规则为 KDD 工作流的附加规则，不改变任何现有门禁流程。
作用：在门禁关键节点输出"模型调度建议"，由用户决定是否手动切换模型。

---

## 触发时机

在以下两个节点必须输出调度建议，其余节点禁止输出（避免噪音）：

1. **知识库阅读完成后、影响分析输出前**
2. **影响分析表格输出后、设计方案输出前**

---

## 复杂度判定标准

根据当前任务命中以下任一条件，判定为"复杂任务"，否则为"轻量任务"：

| # | 复杂信号 | 判定依据 |
|---|----------|----------|
| C1 | 修改状态机或状态流转 | 影响分析中"修改状态流转"为"是" |
| C2 | 修改核心层算法 | 涉及 `src/domain/services/`（如 healingEngine、stringSimilarity） |
| C3 | 修改能力契约或接口契约 | 影响分析中对应项为"是" |
| C4 | 跨模块重构 | 影响分析中"影响其他模块"≥ 2 个 |
| C5 | CRAP 高危函数消缺 | 涉及 CRAP > 16.4 的函数重构 |
| C6 | 架构约束变更 | 需更新 constraints.md 的架构/不变量部分 |

## 轻量信号（全部满足才算轻量）

| # | 轻量信号 |
|---|----------|
| L1 | 仅 UI 样式/文案/布局调整 |
| L2 | 仅知识库文档同步（glossary/lessons/CHANGELOG） |
| L3 | 仅 i18n 词条补充或对称性修复 |
| L4 | 为已有设计补充测试用例 |
| L5 | 代码定位/解释/查询类问答 |

---

## 输出格式

### 复杂任务

```text
【模型调度建议】⚠️
- 命中复杂信号：C1（修改状态机）、C2（涉及 healingEngine）
- 风险：轻量模型可能违反业务不变量或遗漏间接状态转换路径
- 建议：切换至 GLM5.3 后回复"继续"，当前阶段成果已保存可衔接
```

### 轻量任务

```text
【模型调度建议】✅
- 命中轻量信号：L4
- 建议：GLM5.3-Flash 即可胜任，无需切换
```

### 查询类

```text
【模型调度建议】⚡
- 命中轻量信号：L5
- 建议：GLM5.3-FLASHX 足够，快速响应即可
```

---

## 行为约束

1. **建议不阻塞**：调度建议仅提示，不得因用户未切换而拒绝继续执行任务
2. **成果可衔接**：输出建议前的阶段成果（阅读笔记、影响分析表格）必须完整输出，确保用户切换模型后新会话可凭上下文无缝续接
3. **缺省兜底**：无法明确判定时，一律按"复杂任务"建议（宁可高配，不可冒险）
4. **禁止自作主张**：本规则不赋予 Agent 任何切换模型的能力，最终决定权始终在用户
