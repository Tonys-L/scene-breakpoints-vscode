## 1. 核心概念与解决痛点

| 概念 | 传统 VS Code 调试 | Scene Breakpoints 解决方案 |
| :--- | :--- | :--- |
| **断点散落** | 排查多条链路后留下数十个断点，断点频频误停，严重打断调试思路。 | **场景纯净隔离**：激活指定场景时，自动清除其他无关断点，只下发目标断点。 |
| **无描述语义** | 断点列表只显示文件与行号，过两天完全忘记当初为什么打这个点。 | **语义化描述**：支持为每条断点录入中文业务说明，在编辑器和树视图一目了然。 |
| **无法版本化** | 断点只存在本地编辑器的临时缓存中，换电脑或重装后全部丢失。 | **声明式 Git 托管**：统一存盘为 `.vscode/debug-scenes.json`，天然随代码版本库同步。 |
| **代码漂移** | Git Pull 或改动几行代码后，行号位移导致历史断点全部错位。 | **指纹自愈引擎**：结合伴随三行代码特征指纹与滑动窗口加权算法，毫秒级自动找回正确行号。 |

## 2. 5 分钟快速上手

### 步骤 1：添加第一条场景断点
1. 打开任意项目源代码文件；
2. 在任意需要调试的代码行上右键，或按下快捷键 `Ctrl + Alt + B`（macOS: `Cmd + Alt + B`）；
3. 在弹出的输入框中：
   - 选择或输入一个场景名（例如 `login-flow`）；
   - 选择断点类型（默认为普通行断点）；
   - 输入这条断点的业务描述（例如 `校验用户 Token 合法性`）；
4. 保存后，该断点会安全记录在 `.vscode/debug-scenes.json` 中。

### 步骤 2：切换与激活场景
1. 查看 VS Code 底部状态栏，可以看到常驻的场景指示器（初始为 `$(debug-alt) Scene: (None)`）；
2. 点击状态栏，或按下快捷键 `Ctrl + Alt + S`（macOS: `Cmd + Alt + S`）；
3. 选择 `login-flow` 并回车：
   - 工作区中现存的所有其他杂散断点会被自动清空；
   - `login-flow` 场景中配置的所有断点会被瞬间准确下发到编辑器中；
   - 底部状态栏即时变绿高亮显示：`$(check) Scene: login-flow`！

### 步骤 3：反向导出（推荐工作流）
如果你更习惯在调试过程中直接用鼠标在代码行号边上打断点：
1. 随意在编辑器中打好你的行断点、条件断点或 Logpoint；
2. 按 `Ctrl + Shift + P` 呼出命令面板，输入并运行：
   `Scene: 将当前所有断点导出为新场景 (Export Current Breakpoints to Scene...)`；
3. 输入新场景名称（例如 `order-flow`），当前所有断点及其代码指纹就会瞬间被固化到配置文件中！

## 3. 核心功能实战详解

### 3.1 场景隔离与一键激活
当你在大型工程中研读源码时，激活场景会执行**纯净隔离原则**：
- 系统首先清除当前 VS Code 中的断点，防止无关链路的历史断点产生干扰；
- 紧接着把目标场景的断点批量下发；
- 如果你中途想临时清空所有断点，直接按快捷键或在右键菜单选择 `清空所有断点 (Clear All Breakpoints)` 即可，它只会清除当前编辑器里的断点，**绝对不会**误删你存在 JSON 中的场景存档。

### 3.2 五大断点类型支持
Scene Breakpoints 完整对齐 VS Code 原生断点协议：
1. **普通行断点 (Line)**：标准代码行执行暂停；
2. **表达式条件断点 (Condition)**：仅在表达式计算为 `true` 时暂停（如 `user.id === 'admin'`）；
3. **命中计数断点 (Hit Count)**：在被执行指定次数后暂停（如 `> 10` 或 `% 2 === 0`）；
4. **日志断点 (Logpoint)**：在调试控制台打印动态求值日志（支持 `{variable}` 变量插值），全速运行不暂停；
5. **全局函数断点 (Function)**：通过函数名称进行跨文件全局拦截（如 `onMessageReceived`）。

### 3.3 侧边栏树视图与全双工同步
在 VS Code 左侧切换至 **“运行与调试 (Run & Debug)”** 视图，下方提供了专用的 **“场景断点 (Scene Breakpoints)”** 树视图：
- **树视图 $\rightarrow$ 编辑器**：展开任意已激活的场景，直接点击断点前面的原生复选框。勾选即启用、取消即禁用，编辑器中的原生断点实时响应；
- **编辑器 $\rightarrow$ 场景配置**：直接在源码行号上右键禁用断点，配置中的 `enabled` 状态会自动反向持久化写盘；
- **原生高保真视觉**：采用饱满的 16x16 矢量 SVG 断点图标，在选中高亮时永远鲜红饱和，彻底杜绝 VS Code 默认主题冲刷变灰的问题；
- **零闪烁 DOM Diff**：树节点具备唯一稳定 ID，勾选或切换时展开状态和滚动条纹丝不动，体验丝滑。

### 3.4 反向导出当前活跃断点
无需事先构思配置。在调试真实问题时，你可以像往常一样在编辑器各处打断点。调试完成后，使用 **导出当前断点为场景** 命令：
- **新建场景导出**：直接输入新场景名；
- **追加合并到已有场景**：选择已有场景，系统会自动执行同名/同行断点去重更新（Upsert 语义），安全覆盖同位置配置而追加新断点。

### 3.5 多场景叠加与图层组合
复杂端到端链路排查往往需要同时跟踪多个子系统：
1. 点击树视图顶部的多选按钮 `$(checklist)`，或在控制菜单中选择 `多选激活场景 (Multi-select Scenes)`；
2. 自由勾选多个场景（例如 `auth-flow` 和 `payment-flow`）；
3. 确定后，系统会自动合并两者的断点并进行去重，底部状态栏会清晰显示复合激活态：`[auth-flow + payment-flow]`；
4. 你也可以在侧边栏场景项的行内按钮上直接点击 `$(play)` 或 `$(check)`，独立将某个场景叠加进去或单独退出。

### 3.6 场景秒级跨团队分享 (剪贴板)
排查出一个疑难 Bug 需要同事协助时：
1. 在侧边栏右键该场景，选择 `复制场景到剪贴板 (Copy Scene to Clipboard)`；
2. 把生成的标准 JSON 发给同事；
3. 同事在树视图顶部点击 `从剪贴板导入场景 (Import Scene from Clipboard)` 按钮，即可选择覆盖、追加或重命名导入，立刻获得完全一致的调试现场！

## 4. 高级进阶技巧

### 4.1 代码漂移自愈引擎原理解析
当团队成员提交了代码更新、进行了代码格式化，或者增删了几行注释时，源码文件的绝对行号往往会上下移动。

**自愈引擎工作机制：**
1. **指纹采集**：录入或导出断点时，插件会自动采集当前断点行、上一行以及下一行的词法特征指纹；
2. **双向辐射探测**：场景激活时，若发现原行号代码不匹配，自愈算法会以原行号为中心，向上和向下交替辐射扫描（默认范围 $\pm 30$ 行）；
3. **多维加权打分**：
   - 目标行代码相似度（权重 10 分）；
   - 上文环境命中（权重 5 分）；
   - 下文环境命中（权重 5 分）；
   - 缩进深度与词法结构（权重 3 分）；
4. **上下文硬门禁 (Context Guard)**：必须满足上下文至少精准命中一行且置信度达标才认定为命中，绝不单凭单行词法相似度（如仅匹配 `return true`）进行误跳；
5. **静默自愈回写**：命中新位置后，断点精准装配至修正行，同时安全回写更新 `.vscode/debug-scenes.json`。

### 4.2 launch.json 智能联动配置三级优先级
你无需每次调试都手动切换场景。通过配置 `.vscode/launch.json`，在启动 F5 调试的瞬间即可自动预装配好对应场景！

联动匹配遵循严格的**三级优先级策略**：

#### 优先级 1：通过 `env.DEBUG_SCENE` 指定（最高优先级）
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug API Server",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/src/server.ts",
      "env": {
        "DEBUG_SCENE": "api-debug"
      }
    }
  ]
}
```
*提示：支持用逗号隔开多个场景以实现复合激活，如 `"DEBUG_SCENE": "auth-debug, api-debug"`。*

#### 优先级 2：在 `debug-scenes.json` 的 `bindings` 映射表中绑定
```json
{
  "bindings": {
    "Debug API Server": "api-debug",
    "Launch Worker Service": ["worker-init", "worker-exec"]
  }
}
```

#### 优先级 3：智能同名推导（兜底规则）
若前两级均未指定，系统会自动推导是否存在与调试启动项名称同名的场景（大小写不敏感，并自动忽略 `Launch`、`Debug` 等前缀动词）。

*如需关闭此联动特性，可在 VS Code 设置中取消勾选 `sceneBreakpoints.autoActivateOnLaunch`。*

### 4.3 debug-scenes.json 配置文件详解
项目配置文件支持完整的 JSON Schema 校验，语法示例如下：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "bindings": {
    "Start Server": "server-scene"
  },
  "scenes": {
    "server-scene": [
      {
        "type": "line",
        "file": "src/app.ts",
        "line": 42,
        "desc": "服务启动入口",
        "enabled": true
      },
      {
        "type": "condition",
        "file": "src/routes/order.ts",
        "line": 88,
        "condition": "order.amount > 1000",
        "desc": "只拦截大额订单"
      },
      {
        "type": "logpoint",
        "file": "src/utils/logger.ts",
        "line": 15,
        "logMessage": "Order process status: {status}",
        "desc": "免打断链路追踪"
      },
      {
        "type": "function",
        "functionName": "calculateTax",
        "desc": "全局拦截计税函数"
      }
    ]
  }
}
```

## 6. 常见问题解答 (FAQ)

### Q1：为什么激活一个场景后，我之前打的其他断点都不见了？
**A**：这正是本插件的核心设计原则——**“场景隔离与自动净化”**。散落的历史无关断点频繁误停是调试心流的最大杀手。激活场景会自动清除非当前场景的杂散断点。如果你想保留当前断点，请在切换前使用快捷键或右键一键**反向导出**为一个新场景备份即可。

### Q2：我能否同时保留并激活两个以上场景的断点？
**A**：完全可以！你可以使用**多选激活 (Multi-select Scenes)** 特性。点击树视图顶部的多选按钮或在状态栏菜单中自由勾选多个场景，系统会自动合并所有断点并智能去重。

### Q3：断点自愈会修改我的代码源文件吗？
**A**：**绝对不会**。自愈引擎只在激活断点时计算行号位移并下发到 VS Code 调试适配器中，然后更新 `.vscode/debug-scenes.json` 中的行号配置，绝对不会修改你的任何代码源文件。

### Q4：换电脑或推送 Git 后，断点配置会丢失吗？
**A**：不会。所有配置均保存在项目的 `.vscode/debug-scenes.json` 文件中。只要将该文件纳入 Git 仓库管理，团队成员 clone 代码后即可直接开箱即用。
