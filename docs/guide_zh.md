## 1. 你是不是也经常被这些调试破事折磨？

做开发排查问题时，谁没经历过这些痛点：

- 💥 **断点满天飞**：上午查登录留了 8 个点，下午查支付又打了 10 个点。一跑调试，程序在无相关的旧断点上停个没完，脑回路瞬间被打断。
- ❓ **过两天就忘**：看着断点列表里冷冰冰的 `order.ts:142`，完全想不起当初为什么打在这里，只能点进去重新读代码。
- 🕳️ **Git 一拉，断点全偏**：同事提交了代码或者自己格式化了一下，代码行号全变了，原本精心布置的断点全部失效。
- 🤖 **AI 帮忙查 Bug，断点却带不进 IDE**：跟 Cursor、Claude 聊得热火朝天，分析出的关键位置还得自己手动一个个去点红点。

**Scene Breakpoints 就是为了终结这些麻烦而生的！** 它把断点按业务“场景”打包管理，随用随切，行号漂移自动找回，还能直接提交到 Git 仓库全团队共享。

## 2. 3 分钟快速上手

### 第 1 步：给当前行打个场景断点
1. 打开项目里的任意代码文件；
2. 在你想打断点的代码行上按快捷键 `Ctrl + Alt + B`（Mac 是 `Cmd + Alt + B`），或者在代码行上右键选择 `保存当前行断点到场景`；
3. 在弹出的输入框中：
   - 场景名输入一个好记的名字（比如 `login-flow`）；
   - 断点类型选普通行断点即可；
   - 描述里写上一句意图说明（比如 `校验用户 Token 合法性`）；
4. 按回车搞定！如果当前正好开着这个场景，编辑器里的红点会**立刻亮起**。

### 第 2 步：一键切换场景
1. 看一下 VS Code 最底部的状态栏，能看到一个指示器（默认是 `Scene: (None)`）；
2. 鼠标点击状态栏，或者按快捷键 `Ctrl + Alt + S`（Mac 是 `Cmd + Alt + S`）；
3. 选刚才的 `login-flow` 回车：
   - 编辑器里其他乱七八糟的杂散断点会被**秒清空**；
   - 属于 `login-flow` 的断点瞬间装配到位；
   - 底部状态栏变成亮绿色的 `Scene: login-flow`，心里特别踏实！

### 第 3 步：更爽的姿势 —— 反向导出！
其实你平时完全不用先去想怎么配置。就按你平时的习惯，在代码行号旁边用鼠标打好你的断点：
1. 按 `Ctrl + Shift + P` 呼出命令面板；
2. 输入并运行：`Scene: 将当前所有断点导出为新场景`；
3. 起个名字（比如 `pay-bug`），刚刚打好的所有断点连同代码自愈指纹就会自动存下来！

## 3. 日常核心功能与调试技巧

### 3.1 场景隔离与一键激活
大型项目里最烦的就是旧断点干扰。每次你激活一个场景，插件底层会进行智能差量对比：
- 当前已有的相同断点**原地不动**（完全不会闪烁）；
- 不属于当前场景的断点全部**自动摘除**；
- 临时想把屏幕弄干净？按个快捷键执行 `清空当前所有断点` 就行。请放心：它只清理当前编辑器界面，**绝对不会**删掉你存好的场景配置。

### 3.2 各种断点姿势全支持（条件、命中数、日志点等）
VS Code 原生支持的高级断点，这里一个不落：
1. **普通行断点 (line)**：执行到这就停；
2. **条件断点 (condition)**：比如 `user.id === 'admin'`，只有满足条件时才停；
3. **命中次数断点 (hitCount)**：比如循环跑了 100 次之后再停（`> 100`）；
4. **日志断点 (logpoint)**：不停顿代码，直接在调试控制台打日志（支持 `{user.name}` 变量插值，查线上问题神技）；
5. **全局函数断点 (function)**：直接拦截函数名（比如 `handlePayment`），跨文件自动命中。

### 3.3 侧边栏树视图：直观开关与批量控制
点开 VS Code 左侧的 **“运行与调试 (Run & Debug)”** 面板，往下看，能找到 **“场景断点 (Scene Breakpoints)”** 专属视图：
- **直观勾选**：展开场景，断点前面有原生的小勾选框。随手点一下启用/禁用，编辑器里的红点跟着变实变虚；
- **精准定位配置**：鼠标移到断点条目上，点击行内的【定位配置】按钮（文件图标），立刻自动打开 `.vscode/debug-scenes.json` 并精准高亮滚动到该断点所在行；
- **次序微调（上移/下移）**：断点行内提供【上移 ↑】与【下移 ↓】按钮，方便按代码执行流程随心调整断点排序，排序实时就地写盘；
- **调试命中跟随高亮**：按 F5 启动调试命中某个断点停下来时，面板会自动展开所属场景，并在命中节点上渲染显眼的执行指示器（`▶ [当前暂停]` 与绿色栈帧指针），让你时刻掌握当前停在场景的哪一步；
- **反向联动**：在源码行号上右键禁用断点，配置里的状态也会自动更新；
- **右键批量操作**：在场景名字上点右键，能一键启用/禁用场景内所有断点，或者直接克隆一个副本。

### 3.4 反向导出：顺手打的断点，一键存成场景
排查问题时只管随意打断点。调完了觉得“这组断点很有价值，下次肯定还要用”，赶紧呼出命令面板选导出：
- **存为新场景**：输入一个全新的名字；
- **追加到老场景**：选已有的场景，插件会聪明地做合并去重（同一行的新配置覆盖旧配置，新行自动追加进去）。

### 3.5 多场景叠加：查复合链路时的超级杀手锏
排查复杂业务时，往往既要看鉴权，又要看订单，还要看支付：
1. 点击侧边栏场景断点视图顶部的【多选激活】按钮，或者在状态栏菜单里选多选激活；
2. 把 `auth-flow` 和 `order-flow` 同时勾上；
3. 回车确认后，两套场景的断点立刻合二为一，底部状态栏会清楚显示：`[auth-flow + order-flow]`；
4. 你也可以在侧边栏单独点某个场景后面的播放/勾选按钮，随时把某一路追加进来或退出去。

### 3.6 按 F5 启动调试自动联动场景 (bindings)
每次按 F5 调试还要点一下切换场景太麻烦？你可以直接在 `debug-scenes.json` 里加一个 `bindings` 映射：

```json
{
  "bindings": {
    "Debug API Server": "api-debug",
    "Launch Worker": ["worker-init", "worker-exec"]
  },
  "scenes": { ... }
}
```
当你在 VS Code 启动名为 `Debug API Server` 的调试项时，插件会在调试器启动的瞬间自动为你预加载 `api-debug` 场景！完全不需要修改调试参数，零侵入性。*(若未配置 bindings，插件也会尝试查找同名的场景作为兜底推导)*。

### 3.7 复制到剪贴板：一秒把调试现场甩给同事
排查到一半卡住了，想叫同事协助看一眼：
1. 在树视图右键你的场景，点击 `复制场景到剪贴板`；
2. 打开聊天窗口粘贴发给同事；
3. 同事只要在树视图顶部点击【从剪贴板导入】按钮，就能一键还原出一模一样的断点现场；
4. 就算你复制的时候带了 Markdown 代码块（````json ... ````）或者 JSONC 注释，插件底层也会自动帮你洗干净，完全不挑格式。

## 4. 代码漂移与自愈原理（断点怎么自动跟过去？）

代码只要有人动，行号就一定会上下跑偏。普通的断点只记录死板的数字（比如第 42 行），代码一改就错位。本插件通过**代码指纹**与**两阶段自愈算法**彻底解决了这个问题。

### 4.1 什么是代码指纹？（三行上下文机制）
当你在编辑器保存断点或执行“反向导出”时，插件不光记下了行号，还会自动提取断点所在行、上一行以及下一行的真实源码，形成一个三行特征指纹（`contextSnippet`）：

```json
"contextSnippet": {
  "before": "const port = process.env.PORT || 3000;",
  "current": "app.listen(port, () => {",
  "after": "  logger.info(`Server running on ${port}`);"
}
```
有了这三行代码作为指纹线索，后续无论当前文件插入了多少空行、增加了多少新代码，插件都能像雷达一样精准定位到这句 `app.listen`。

---

### 4.2 两阶段自愈引擎：近距辐射 + 作用域巡航
当场景被激活时，若发现原行号的代码不匹配了，自愈引擎会按以下两阶段展开搜索：

- **阶段一：原址附近小范围双向辐射探测（上下 30 行）**  
  以原行号为中心双向交替向外辐射扫描。它不仅匹配目标行的文本相似度，还会穿透空行比对上下文骨架以及缩进深度。最关键的是设有**“当前行本体守卫”**：必须有目标行代码确实存在的强力依据，绝不因为周围的代码长得像就胡乱漂移！
- **阶段二：大范围函数作用域巡航（突破 30 行限制）**  
  如果有人在文件顶部新加了 100 行代码，或者把整个函数重构搬到了文件尾部怎么办？  
  断点在录入时自动记录了所在函数的名字（`scopeAnchor`）。只要阶段一没找到，阶段二就会在全文件范围内搜寻这个函数声明行，把扫描焦点动态重新锚定到函数体内（哪怕整体位移了 50 到 500 行），毫秒级把断点抓回来！原生支持 Python、Go、Rust、TS/JS、Java、C++、C# 等多门语言。
- **自愈行号持久化回写**：自愈成功后，插件会自动把计算出的**最新有效行号回写更新到 `debug-scenes.json`** 中，完成自愈闭环。

---

### 4.3 代码彻底被删除了怎么办？（脱靶警告）
如果那段代码确实被彻底删除或面目全非了，自愈引擎坚决不瞎猜：
- 自动判定为 `unmatched`（脱靶状态）；
- 保守降级：断点仍然停在原行号作为占位提示，激活完成后 VS Code 会弹出一个醒目的警告弹窗，点击可以快速定位源码；
- 侧边栏的树视图里，这个断点前面会贴一个明显的 `[未匹配]` 黄色警告标签，鼠标悬浮上去还能看诊断说明。

## 5. AI Agent 协同与技能编排

### 5.1 插件是如何与 AI 协同工作的？（声明式驱动机制）

以前让 AI 助手（Cursor、Windsurf、GitHub Copilot、Claude Code 等）帮忙排查 Bug 时，最痛苦的是**断点无法落地**：AI 在聊天框里分析得头头是道，告诉你“应该去某某文件的第 45 行看看变量”，但它**无法操控你的 IDE 界面**。你得在多个文件之间来回翻找，用鼠标一个个把红点补上，极容易点错行，调试思路也被打得稀碎。

**Scene Breakpoints 采用了一套极简优雅的“声明式契约”解决这个问题：**

1. **AI 只做它最擅长的事：读写纯文本配置**  
   AI 不需要任何特殊的权限或复杂的环境，它只需要像编辑普通代码一样，读写项目根目录下的 `.vscode/debug-scenes.json`。
2. **插件作为底层执行引擎：实时监听并驱动 IDE**  
   插件在后台静默监听该文件的变动。只要 AI 把分析出来的断点写进文件并激活，插件就会在毫秒级内调用 VS Code 官方调试协议（DAP），**把红点直接打在你的代码编辑器里**！
3. **Skill（技能规则）：给 AI 装上专业知识**  
   为了让 AI 知道什么时候该打断点、按什么格式写配置，插件提供了标准的 Skill 规则文件。装上之后，AI 就会像一位经验丰富的排障专家，在对话中自动为你编排断点。

---

### 5.2 安装 AI 技能 (Skill)：何时使用与核心场景
按 `Ctrl + Shift + P` 运行：
`Scene Breakpoints: 安装 AI Agent 技能/规则...`
可以一键将技能文件安装到项目目录中，主流 AI 工具会自动感知并加载它：

- **Cursor**：`.cursor/rules/scene-breakpoints.mdc`
- **Windsurf**：`.windsurf/rules/scene-breakpoints.md`
- **Cline**：`.clinerules/scene-breakpoints.md`
- **Roo Code**：`.roorules/scene-breakpoints.md`
- **Continue**：`.continue/prompts/scene-breakpoints.prompt`
- **VS Code / Copilot**：`.github/skills/scene-breakpoints/SKILL.md`
- **Trae**：`.trae/skills/scene-breakpoints/SKILL.md`
- **Antigravity**：`.agents/skills/scene-breakpoints/SKILL.md`

#### AI 技能的核心触发场景
安装后，当你在对话中向 AI 表达以下需求时，AI 会自动调用该技能为你布设断点：
1. **Bug 排查与异常诊断**：“帮我调试下这个报错，在关键代码处打好断点”、“分析调用栈并在可疑路径设断点”；
2. **源码研读与业务导览 (Code Tour)**：“带我看下登录/结算核心流程，顺着主干帮我布置一套导览断点”；
3. **复杂条件探测**：“这个循环跑了几万次，只在某个条件满足时停下（生成条件断点）”、“用日志断点打印变量”；
4. **断点场景整理**：“我要查另一个模块了，把当前这组断点存为场景”、“为支付流程建立独立断点场景”。

### 5.3 AI 是如何帮你布置并激活断点的（三种激活途径）

AI 生成场景后，有以下三种途径让断点生效：

#### 途径 1：`debug-scenes.json` 启动项联动绑定（最推荐，体验最丝滑 ⭐⭐⭐）
- **操作方式**：AI 获取你项目的调试启动项名称（比如 `"Launch Program"`），直接在 `debug-scenes.json` 的 `bindings` 里配置映射：
  ```json
  "bindings": {
    "Launch Program": ["auth-login-flow"]
  }
  ```
- **优势**：**完全无需额外配置权限！** 用户一按 F5，插件在启动瞬间自动装配对应场景断点并清空杂散点，体验开箱即用。

#### 途径 2：声明式即时自动激活（AI 静默打点 ⭐⭐）
- **操作方式**：AI 在 `debug-scenes.json` 根级写入 `"activeScenes": ["auth-login-flow"]`。
- **前置权限**：为防止误触，需在工作区 `.vscode/settings.json` 中开启授权开关：
  ```json
  {
    "sceneBreakpoints.allowAiFileActivation": true
  }
  ```
  *(AI 可以在首次初始化时顺手写入此配置)*。清空断点时，AI 将该字段改为 `[]` 即可。

#### 途径 3：侧边栏视觉手动切换（兜底方案 ⭐）
- **操作方式**：AI 提示用户：“已为您生成场景 `auth-login-flow`，可以在左侧【运行与调试】展开【Scene Breakpoints】，点击该场景后面的激活按钮即可生效”。

---

### 5.4 AI 编写断点的数据格式规范（指纹推荐缺省）

AI Agent 在生成断点时需遵循以下原则：

1. **语法硬规则：条件断点的 type 必须是 `"condition"`**
   - ❌ 错误：`{ "type": "conditional", "condition": "x > 5" }`（会被底层丢弃，退化为普通断点）
   - ✅ 正确：`{ "type": "condition", "condition": "x > 5" }`

2. **描述（desc）写意图，不要写机械行号**
   - ✅ 好的写法：`"检查 user 实体是否为 null"`、`"观察 retryCount 是否超限"`
   - ❌ 坏的写法：`"第 45 行"`、`"if 语句"`

3. **自愈指纹（contextSnippet）推荐缺省不写**
   - 很多开发者会问：既然上一章讲了断点自愈依赖三行代码指纹，那 AI 写配置时要不要把这三行代码也生成出来？
   - **强烈建议 AI 缺省不写！** AI 只需提供 `type`、`file`、`line` 和 `desc`。
   - 插件在激活时对无指纹断点原样信任并下发，这极大避免了大模型猜测上下文消耗过多 Token 甚至产生空格格式化幻觉；
   - 后续你在编辑器里微调、通过菜单保存或反向导出时，插件自己会去读磁盘源码，把真实的三行指纹自动提取补齐。

---

### 5.5 诊断面板：检查 AI 集成状态
按 `Ctrl + Shift + P` 运行：
`Scene Breakpoints: 诊断 AI Agent 集成状态...`
集中查看：
- 外部文件监听权限（`allowAiFileActivation`）开启了没有；
- 当前激活了哪些场景；
- 各主流 AI 规则文件哪些已安装、版本是否最新。未安装的点击即可一键补齐。

### 5.6 升级插件后，我手改过的规则会被冲掉吗？
**绝对不会！** 插件充分尊重你的私有提示词定制：
1. **秒辨状态**：
   - 没改过的纯官方版：面板标注为 `[最新]` 或 `[可平滑升级]`（点击一键无痛升级）；
   - 自己加过规则的定制版：面板标注为 `[已自定义]`。
2. **VS Code 原生并排 Diff 比对**：
   点击已自定义的规则条目，选择“查看差异比对”，VS Code 会弹出一个左右并排的 Diff 窗口（左侧为你的私有文件，右侧为官方最新模板），你可以像审代码一样挑着合并；
3. **覆盖前强制备份**：
   哪怕选择了覆盖，插件也会在动手前一刻，自动在同目录下建一个带时间戳的备份文件（比如 `SKILL.2026-09-13T01-20-00-000Z.bak`），后悔随时能找回！

## 8. 常见问题解答 (FAQ)

### Q1：为什么切了一个新场景，我之前打的断点就都不见了？
**A**：这不是 Bug，这正是插件的核心设计！调试最怕无关断点胡乱暂停。切换新场景时会自动清场，让你专心排查当前链路。如果你想保留手头这组断点，切换前用命令面板花 2 秒钟**反向导出**成一个新场景存起来即可。

### Q2：我能不能同时开着两个场景的断点？
**A**：当然可以！用**多选激活**功能。在树视图点一下【多选激活】按钮，把你要的几个场景全勾上，插件会自动把两边的断点拼在一起，完全不冲突。

### Q3：自愈引擎会改动我的代码源文件吗？
**A**：**绝对不会！** 借它一百个胆子也不敢动你的代码。它算出行号漂移后，只是通知 VS Code 把调试红点挪到新行号上，并且把 `.vscode/debug-scenes.json` 里的数字更新一下，你的业务源码一行都不会被改变。

### Q4：换电脑或者推送代码后，配置还在吗？
**A**：只要你把 `.vscode/debug-scenes.json` 提交到 Git 里，不管换到哪台电脑、哪个同事拉了代码，所有调试场景开箱即用，断点一个都不会丢。

### Q5：我手动修改过的 AI 规则，插件更新后会被强制覆盖吗？
**A**：**绝对不会！** 插件有指纹比对机制，知道你改过文件，会打上“已自定义”的标记。你可以选择打开并排 Diff 窗口像审代码一样自己挑着合入；哪怕选择覆盖，插件也会在覆盖前自动备份一个 `.bak` 文件，保障你的劳动成果百分百安全。
