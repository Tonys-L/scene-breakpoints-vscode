## 1. 概述

### 1.1 目标

允许场景声明中以内联引用（`{ "type": "scene", "name": "..." }`）复用其他场景的断点集合：

```json
{
  "auth-core": [
    { "type": "line", "file": "src/auth.ts", "line": 12 },
    { "type": "line", "file": "src/session.ts", "line": 45 }
  ],
  "payment-debug": [
    { "type": "scene", "name": "auth-core" },
    { "type": "line", "file": "src/payment.ts", "line": 40 },
    { "type": "condition", "file": "src/payment.ts", "line": 88, "condition": "amount > 1000" }
  ]
}
```

业务价值：

- 消除通用链路断点（认证/DB 连接等）在多场景中的重复定义
- 执行时序 100% 保真：引用按声明位置展开，穿插顺序即执行顺序
- AI 生成配置省 Token 60%+（一行引用替代 N 行断点）
- skills 新增"模块地图"教学法，使 AI 天然产出引用结构（特性②）

### 1.2 核心设计主张

**两个世界，一个收窄点**：

| 世界 | 内容 | 类型形态 |
|---|---|---|
| 声明世界 | Scene 内部有序步骤流：具象断点 + 引用节点穿插 | `SceneStep[]`（多态） |
| 物理世界 | 自愈、指纹、DAP 装配只认"文件+行号"断点 | `Breakpoint[]`（同质） |

两世界通过 `sceneResolver` 单一收窄点连接：`getSteps(): SceneStep[]` 无法直接喂给任何 `Breakpoint[]` 签名——**编译器强制所有下游必须经过解析**，"忘记展开引用"这类静默丢失断点的缺陷在类型层面不可能发生。

```ts
import type { SceneItem } from "#src/domain/types";

/**
 * 场景步骤协议 —— 声明世界最小行为契约
 * 只收编有真实消费者的行为，拒绝胖接口：
```

### 2.4 SceneRef 实体（与 sceneStep.ts 同文件或 `sceneRef.ts`）

```ts
import type { SceneRefItem, SceneItem } from "#src/domain/types";
import type { SceneStep } from "./sceneStep";

/** 场景引用实体：声明世界的引用节点，纯数据 + 协议行为，不持有 catalog（展开是解析器职责） */
export class SceneRef implements SceneStep {
  public readonly kind = "scene-ref" as const;

  constructor(
    public readonly name: string,
    public desc?: string,
    public enabled: boolean = true,
  ) {}

  public matches(other: SceneStep): boolean {
    return other instanceof SceneRef && other.name === this.name;
  }

  public toggle(): void {
    this.enabled = !this.enabled;
  }

  /** 缺省不落盘：enabled === true 与 desc === undefined 时不写键，保持 JSON 最小形状 */
  public toJSON(): SceneRefItem {
    const out: SceneRefItem = { type: "scene", name: this.name };
    if (this.desc !== undefined) out.desc = this.desc;
    if (this.enabled === false) out.enabled = false;
    return out;
  }

  /** 工厂：从 DTO 构造（name 非空校验） */
  public static from(dto: SceneRefItem): SceneRef | undefined {
    const name = dto.name?.trim();
    if (!name) return undefined;
    return new SceneRef(name, dto.desc?.trim() || undefined, dto.enabled !== false);
  }
}
```

## 3. sceneResolver 设计（`src/domain/services/sceneResolver.ts`，新建）

无状态纯函数 Service（ADR-004 判定法则：无状态 + 纯计算 = Service），无宿主依赖、无 IO、无锁。

### 3.1 接口

```ts
import { Breakpoint } from "#src/domain/models/breakpoint";
import { SceneCatalog } from "#src/domain/models/sceneCatalog";

/** 展开后的步骤：断点 + 溯源信息 */
export interface ResolvedStep {
  breakpoint: Breakpoint;   // 源场景中的实体引用（非克隆，与现状 merge 行为一致）
  ownerScene: string;       // 该断点的**定义**所在场景名（回写路由目标）
  refPath: string[];        // 引用链（不含定义场景自身），如 ["payment-debug", "auth-core"]
}

export type ResolveWarning =
  | { code: "dangling-ref"; refName: string; refPath: string[] }   // 悬空：目标场景不存在
  | { code: "disabled-ref"; refName: string; refPath: string[] };  // 禁用跳过（信息级）

/** 成环错误：携带完整环路径，如 ["a", "b", "c", "a"] */
export class CircularReferenceError extends Error {
  public readonly name = "CircularReferenceError";
  constructor(public readonly cyclePath: string[]) {
    super(`Circular scene reference: ${cyclePath.join(" → ")}`);
  }
}

export interface ExpandResult {
  steps: ResolvedStep[];        // 严格声明序的扁平断点流（已做跨场景 INV-011 去重）
  warnings: ResolveWarning[];
}

/** 单场景展开 */
export function expandScene(catalog: SceneCatalog, sceneName: string): ExpandResult;

/** 多场景展开（激活管道入口）：按 targetScenes 顺序逐场景展开，跨场景先到先得去重 (INV-011) */
export function expandScenes(catalog: SceneCatalog, sceneNames: string[]): ExpandResult;
```

### 3.2 参考实现（完整 TypeScript，可直接落地）

```ts
// src/domain/services/sceneResolver.ts
import { Breakpoint } from "#src/domain/models/breakpoint";
import { SceneRef } from "#src/domain/models/sceneRef";
import { SceneCatalog } from "#src/domain/models/sceneCatalog";
import type { SceneStep } from "#src/domain/models/sceneStep";

/** 引用链深度上限（双保险：防超长链与资源耗尽；含根场景在内最多 32 层） */
const MAX_REF_DEPTH = 32;

// ---------- 对外接口（§3.1 已定义，此处含实现） ----------

export class CircularReferenceError extends Error {
  public override readonly name = "CircularReferenceError" as const;
  constructor(public readonly cyclePath: string[]) {
    super(`Circular scene reference: ${cyclePath.join(" -> ")}`);
  }
}

/**
 * 断点位置键 —— 与 Breakpoint.matches 等价判据：
 * function 按 functionName；其余按归一化 file + line。
 * 保证与现有 Scene.merge 去重语义逐字节一致（INV-011）。
 */
function breakpointKey(bp: Breakpoint): string {
  if (bp.type === "function") return `fn:${bp.functionName}`;
  const normFile = (bp.file ?? "").replace(/\\/g, "/").toLowerCase();
  return `src:${normFile}:${bp.line}`;
}

/**
 * 单场景 DFS 展开（内部递归）。
 * refPath 语义：从根场景到当前场景的引用链（含两端）。
 * ownerScene 隐含于 sceneName 参数 —— 断点的定义场景即其所在场景。
 */
function dfs(
  catalog: SceneCatalog,
  sceneName: string,
  refPath: string[],
  seen: Set<string>,
  output: ResolvedStep[],
  warnings: ResolveWarning[],
): void {
  const scene = catalog.getScene(sceneName);
  if (!scene) return; // 调用方已 has() 守卫，防御性兜底

  for (const step of scene.getSteps()) {
    if (step.kind === "breakpoint") {
      const key = breakpointKey(step as Breakpoint);
      if (seen.has(key)) continue;            // INV-011 先到先得
      seen.add(key);
      output.push({ breakpoint: step as Breakpoint, ownerScene: sceneName, refPath });
      continue;
    }

    // ---- SceneRef 分支 ----
    const ref = step as SceneRef;

    if (!ref.enabled) {                        // 禁用：整棵子树跳过（含其下游悬空，不报告）
      warnings.push({ code: "disabled-ref", refName: ref.name, refPath });
      continue;
    }
    if (!catalog.has(ref.name)) {              // 悬空：警告 + 跳过，其余断点正常输出
      warnings.push({ code: "dangling-ref", refName: ref.name, refPath });
      continue;
    }
    if (refPath.includes(ref.name)) {          // 成环：当前链上重复即环
      const start = refPath.indexOf(ref.name);
      throw new CircularReferenceError([...refPath.slice(start), ref.name]);
    }
    if (refPath.length >= MAX_REF_DEPTH) {     // 深度上限双保险
      throw new CircularReferenceError([...refPath, ref.name]);
    }
    dfs(catalog, ref.name, [...refPath, ref.name], seen, output, warnings);
  }
}

/** 单场景展开 */
export function expandScene(catalog: SceneCatalog, sceneName: string): ExpandResult {
  const output: ResolvedStep[] = [];
  const warnings: ResolveWarning[] = [];
  const seen = new Set<string>();

  const root = catalog.getScene(sceneName);
  if (!root) {
    return { steps: output, warnings: [{ code: "dangling-ref", refName: sceneName, refPath: [] }] };
  }

  if (!root.hasSceneRefs()) {                  // 恒等快路径：无引用直出，零递归
    for (const step of root.getSteps()) {
      const bp = step as Breakpoint;           // kind 收窄：无引用场景 steps 恒为断点
      const key = breakpointKey(bp);
      if (seen.has(key)) continue;
      seen.add(key);
      output.push({ breakpoint: bp, ownerScene: sceneName, refPath: [sceneName] });
    }
    return { steps: output, warnings };
  }

  dfs(catalog, sceneName, [sceneName], seen, output, warnings);
  return { steps: output, warnings };
}

/** 多场景展开（激活管道入口）：按声明序逐场景展开，跨场景先到先得 (INV-011) */
export function expandScenes(catalog: SceneCatalog, sceneNames: string[]): ExpandResult {
  const output: ResolvedStep[] = [];
  const warnings: ResolveWarning[] = [];
  const seen = new Set<string>();              // 跨根共享：多场景激活整体先到先得

  for (const name of sceneNames) {
    const root = catalog.getScene(name);
    if (!root) continue;                       // 幽灵场景已在 catalog.activate 过滤，防御性兜底
    if (root.hasSceneRefs()) {
      dfs(catalog, name, [name], seen, output, warnings);
    } else {                                   // 恒等快路径
      for (const step of root.getSteps()) {
        const bp = step as Breakpoint;
        const key = breakpointKey(bp);
        if (seen.has(key)) continue;
        seen.add(key);
        output.push({ breakpoint: bp, ownerScene: name, refPath: [name] });
      }
    }
  }
  return { steps: output, warnings };
}
```

**实现级修正记录**（相对 1.0 版伪码）：

| 修正点 | 1.0 伪码 | 2.0 实现 | 理由 |
|---|---|---|---|
| 成环检测 | `visited` 集合 + add/delete 回溯 | `refPath.includes(ref.name)` | 语义等价（环 = 当前链上重复出现）；深度 ≤ 32 使 includes 开销可忽略；省去集合管理，消除回溯遗漏风险 |
| 环路径还原 | `[...refPath, step.name]`（含前缀） | `refPath.slice(indexOf(ref.name))` + 闭合 | U5 期望 `["A","B","A"]` 而非 `["A","B","A","B","A"]` 之类前缀噪声——从环入口截取 |
| 恒等快路径 | 未明确位置 | `expandScene`/`expandScenes` 各自独立短路 | 无引用场景占存量配置绝大多数，短路保证零递归开销 |
| 多根 seen | 未明确 | `expandScenes` 层共享一个 `seen` | 多场景叠加激活时跨根先到先得，与现 `Scene.merge(activeScenes)` 语义一致 |

**CRAP 控制拆分**：`expandScene` / `expandScenes` / `dfs` / `breakpointKey` 四函数各司其职，单函数圈复杂度 ≤ 8（GR-014 红线内）。

### 3.3 语义规则表

| 规则 | 行为 | 依据 |
|---|---|---|
| 时序保真 | 输出严格按声明序深度优先展开，引用与断点穿插即执行顺序 | roadmap 特性① |
| 成环阻断 | 进入任何写盘/DAP 之前抛 `CircularReferenceError`，激活整体中止 | roadmap：配置错误必须显式失败 |
| 悬空降级 | 警告 + 跳过该子树，**其余断点正常下发** | roadmap：防调试会话中断 |
| 禁用跳过 | `enabled: false` 引用整棵子树跳过（信息级警告，可在结果中静默） | 子场景级开关 |
| 菱形 DAG | 合法：A 引 B、C；B、C 各引 D → D 展开两次（除非跨场景 seen 去重） | 回溯式 visited |
| 同名去重 | resolver 的 `seen` 与 INV-011 判据完全一致，替代原 `Scene.merge` 的去重职责 | 不变量保持 |
| 恒等快路径 | `!scene.hasSceneRefs()` 时逐条直出（等价现 merge 行为），零递归开销 | 向后兼容 |

### 5.2 persistHealedBackfill 溯源路由（重写，完整实现）

现状缺陷：只回填 `validTargetScenes` —— 引用的断点定义在**非激活**场景（auth-core 未激活、仅被 payment-debug 引用）时无法回写。

```ts
/**
 * 将自愈和富化后的最新行号与指纹回写持久化至各个**定义场景** (INV-004, INV-010, INV-030.6)
 * 变更：输入从 mergedBreakpoints 改为带溯源的展开流；回写目标从 validTargetScenes 改为 ownerScenes 唯一集
 */
export function persistHealedBackfill(
  workspaceRoot: string,
  catalog: SceneCatalog,
  validTargetScenes: string[],                  // 保留参数（事件/日志用），回写不再依赖
  applyResult: ApplySceneResult,
  resolved: ResolvedStep[],                     // ← 溯源路由依据
  sceneRepository: ISceneRepository,
): void {
  const candidateInstances = applyResult.healedBreakpoints?.length
    ? applyResult.healedBreakpoints.map((b: SceneBreakpoint | Breakpoint) =>
        b instanceof Breakpoint ? b : new Breakpoint(b),
      )
    : resolved.map((s) => s.breakpoint);        // 无 DAP healed 时回退到展开流实体（现状行为等价物）

  // 溯源路由：按定义场景唯一集回写（含未被激活的被引用场景）
  const ownerScenes = [...new Set(resolved.map((s) => s.ownerScene))];
  for (const owner of ownerScenes) {
    catalog.getScene(owner)?.backfillHealed(candidateInstances);
  }
  sceneRepository.saveScenesConfig(workspaceRoot, catalog.toJSON());
}
```

### 5.2.1 executeSceneActivation 改造后完整代码（变更段）

```ts
import { expandScenes, CircularReferenceError, type ResolvedStep } from "#src/domain/services/sceneResolver";
import type { SceneItem } from "#src/domain/types";

export async function executeSceneActivation(
  params: ExecuteSceneActivationParams,
): Promise<ActivateSceneResult> {
  const { workspaceRoot, targetScenes, deps } = params;
  const { sceneRepository, breakpointBridge, lineReader } = deps;
  if (!sceneRepository || !breakpointBridge) {
    throw new Error("SceneService: sceneRepository and breakpointBridge must be configured");
  }

  lineReader?.clearCache?.();

  const config = sceneRepository.loadScenesConfig(workspaceRoot);
  const catalog = new SceneCatalog(config);

  // 1. 过滤幽灵场景与有效性校验 (INV-009) —— 不变
  const actResult = catalog.activate(targetScenes);
  if (!actResult.success) {
    return { success: false, validTargetScenes: [], missingScenes: actResult.missingScenes,
             loadedCount: 0, healedCount: 0, unmatchedCount: 0 };
  }
  const validTargetScenes = actResult.validTargetScenes;
  const missingScenes = actResult.missingScenes;

  // 2. 【变更】场景组合解析：展开引用为纯断点流（INV-030.1/30.2）
  //    成环在此抛出 CircularReferenceError —— 早于任何状态机写入 / DAP 下发 / 磁盘落盘
  //    悬空/禁用降级为 warnings，不阻断激活（INV-030.4/30.5）
  const { steps: resolvedSteps, warnings: resolveWarnings } = expandScenes(catalog, validTargetScenes);
  const mergedBreakpoints = resolvedSteps.map((s) => s.breakpoint);

  // 3. 应用层前置自愈与指纹富化管道 —— 不变（输入 Breakpoint[]，实体引用语义与现状一致）
  const {
    healedCount: appHealedCount,
    enrichedCount: appEnrichedCount,
    unmatched: unmatchedBreakpoints,
  } = await enrichAndHealBreakpoints(workspaceRoot, mergedBreakpoints, lineReader);

  // 同步状态机脱靶失联警告 (INV-004) —— 不变
  sceneStateManager.setUnmatchedBreakpoints(
    unmatchedBreakpoints.map((bp) => `${bp.file.replace(/\\/g, "/")}:${bp.line}`),
  );

  const bpsToLoad = mergedBreakpoints.map((b) => b.toJSON());   // 展开流已同质，DTO 形状与现状一致
  const primarySceneLabel = validTargetScenes.length === 1 ? validTargetScenes[0] : validTargetScenes.join(" + ");

  // 4. 权威持久化 SSOT 写入约束 (INV-010) —— 不变
  syncDiskActiveScenesIfNeeded(workspaceRoot, catalog, config.activeScenes, validTargetScenes, sceneRepository);

  // 5. 装配断点至宿主调试器 (INV-002, INV-005) —— 不变
  sceneStateManager.setApplyingState(true);
  let applyResult;
  try {
    applyResult = await breakpointBridge.applySceneBreakpoints(workspaceRoot, primarySceneLabel, bpsToLoad);
  } finally {
    sceneStateManager.setApplyingState(false);
  }

  // ... loadedCount/healedCount/enrichedCount/finalUnmatched 汇总逻辑不变 ...

  // 6. 投影更新至内存状态机 (INV-004) —— 不变
  sceneStateManager.setLastAppliedTopologyHash(computeTopologyHash(bpsToLoad));
  activeBreakpointIndex.sync(workspaceRoot, catalog.toJSON().scenes, validTargetScenes);
  sceneStateManager.setActiveScenes(validTargetScenes, loadedCount);

  // 7. 【变更】自愈溯源回写闭环：按 ownerScene 路由（原为 validTargetScenes）
  if (healedCount > 0 || enrichedCount > 0) {
    persistHealedBackfill(workspaceRoot, catalog, validTargetScenes, applyResult, resolvedSteps, sceneRepository);
  }

  appEventBus.emit("scene:activated", { workspaceRoot, activeScenes: validTargetScenes });
  // 【新增】解析警告事件（悬空/禁用），UI 订阅后以 Warning 级通知展示，不阻断
  if (resolveWarnings.length > 0) {
    appEventBus.emit("scene:resolve-warnings", { workspaceRoot, warnings: resolveWarnings });
  }

  return { /* 现有字段全部不变 */ };
}
```

路由规则：`ownerScene` = 断点**定义**所在场景（非引用发起场景）。同源多引用：resolved 流中同一实体经 INV-011 至多出现一次，且 `ownerScenes` 去重 → **天然单次回写**。引用项自身（SceneRef）永不接收回写（backfillHealed 内部 kind 收窄已保证）。

### 5.3 成环失败路径（锁时序与状态机）

```
       │                                                      setActiveScenes / 任何 saveScenesConfig

sceneManager 捕获（既有 catch 分支）:
  └─ showErrorMessage(`场景引用成环: ${cyclePath.join(" → ")}`)
```

- 状态机无新增状态/转换：复用"配置无效"失败路径语义，flows.md 状态机图零变更

````markdown
当目标调试链路横跨多个模块时，**不要平铺重复断点**——先画模块地图，再组合引用。

### 三步生成法

1. **识别通用链路**：认证、数据库连接、消息队列、日志等基础设施代码，
   沉入底层场景（命名惯例 `xxx-core`）：

   "auth-core": [
     { "type": "line", "file": "src/auth.ts", "line": 12, "desc": "token 校验入口" },
     { "type": "line", "file": "src/session.ts", "line": 45, "desc": "会话续期" }
   ]

2. **业务场景组合引用**：业务调试场景用 `{"type":"scene"}` 引用通用链路，
   只补充业务特有断点：

   "payment-debug": [
     { "type": "scene", "name": "auth-core", "desc": "支付前必过认证" },
     { "type": "line", "file": "src/payment.ts", "line": 40, "desc": "下单入口" },
     { "type": "condition", "file": "src/payment.ts", "line": 88,
       "condition": "amount > 1000", "desc": "大额支付风控" }
   ]

3. **声明顺序 = 执行顺序**：引用与断点穿插排列，激活时按声明位置深度优先展开，
   时序 100% 保真。

### 引用硬规则（违反将导致激活失败或降级）

- 被引用场景必须**先在本文件中声明**（同文件内按 name 解析，不支持跨文件引用）
- **禁止自引用与任何形式的环**：A→B→A 会在激活时报错并显示完整环路径
- 引用条目可 `"enabled": false` 临时摘除整棵子场景（不删配置）
- 引用悬空（name 不存在）→ 激活时警告并跳过，其余断点正常下发

### 收益

- 通用链路断点只维护一处，改一处全场景生效
- AI 生成配置省 Token 60%+（一行引用替代 N 行断点）
- 激活时自动按模块去重（先到先得）
````

配套：`agentSkillService.ts` 的技能资产导出（agent-rule-asset）同步携带该章节，使外部 AI Agent 拿到的规则资产含组合写法（拓扑哈希输入含引用条目，配置漂移检测自动覆盖）。

## 8. INV-030（新增不变量，批次 5 落入 constraints.md）

> **INV-030 场景引用解析不变量**
> 1. 含引用场景的激活必须先经 `sceneResolver` 展开，产出纯断点流后方可进入合并/自愈/DAP 管道；该约束由 `getSteps(): SceneStep[]` 与 `Breakpoint[]` 的类型隔离在编译期强制（禁止绕过收窄点直接消费声明世界）。
> 2. 展开严格保持声明时序（深度优先、按序穿插）。
> 3. 引用成环必须在任何写盘/DAP 下发之前抛出 `CircularReferenceError`（携带完整环路径），状态机不得进入中间态，磁盘零污染。
> 4. 悬空引用降级为警告并跳过，不得中断其余断点的激活。
> 5. `enabled: false` 的引用整棵子树跳过。
> 6. 自愈回写按 `ownerScene`（断点定义场景）路由，同源多引用至多回写一次；引用节点自身永不接收回写。
> 7. 引用条目在 codec 清洗往返中不得丢失（保真往返）；非法引用（空 name）在清洗阶段丢弃。
