# 项目概览

> ⚠️ AI 首次接触项目时必须阅读本节，理解业务上下文后再读代码。

## 系统定位

Scene Breakpoints (场景断点管理器) 是一个专为复杂业务调试与源码研读打造的轻量高效开发工具。它允许开发者按业务场景隔离、编排与秒级切换断点集合，并提供基于三行上下文代码指纹的自愈引擎，自动抵御 Git 代码变动引发的断点漂移。

## 业务背景

1. **断点散落与心流打断**：日常排查订单、鉴权或支付等不同链路时，断点遍布在几十个文件中。切换排查任务时，无关的历史断点频频误停，严重打断调试心流。
2. **缺乏版本化协同**：原生 VS Code 断点存储在本地内存或闭源工作区缓存中，换电脑或团队协同排查 bug 时无法一键共享调试现场。
3. **代码变更导致断点漂移**：团队拉取最新代码（Git Pull）或增删注释后，绝对代码行号发生移动，导致保存的断点全部错位失效。

## 项目目标

1. **场景纯净隔离**：激活指定场景时，自动清除工作区其他散落的无关断点，只下发目标场景的断点；
2. **全类型断点支持**：无缝支持行断点、条件表达式断点、命中计数断点、日志断点（Logpoint）与跨文件全局函数断点；
3. **代码行号漂移自愈**：基于伴随三行代码特征指纹与双向滑动窗口加权算法，毫秒级自动找回真实断点并回写校准；
4. **架构解耦与跨端潜力**：断点规范（JSON）与核心算法与宿主编辑器解耦，为未来适配 JetBrains / Neovim 等多 IDE 奠定基础。

## 核心业务关系

| 模块 | 关联模块 | 影响方向 | 影响说明 |
|------|----------|----------|----------|
| `commands/applyScene` | `sceneStateManager` | 命令 → 状态机 | 场景激活成功后，通知状态机更新全局激活场景与状态 |
| `commands/applyScene` | `breakpointAdapter` | 命令 → DAP适配器 | 下发场景断点集合，执行原生清除与批量注入 |
| `breakpointAdapter` | `healingAdapter` | 适配器 → 自愈引擎 | 下发代码行断点前，调用自愈算法探测并返回修正行号 |
| `breakpointAdapter` | `sceneStateManager` | 适配器 → 状态机 | 清除与装载断点期间设置原子锁（`isApplying`），防止触发状态栏闪烁 |
| `commands/applyScene` | `configManager` | 命令 → 配置管理 | 检测到行号自愈漂移时，显式将更新后的断点持久化回写至 `.vscode/debug-scenes.json` |
| `sceneStateManager` | `statusBar` | 状态机 → 视图(View) | 基于 EventEmitter 响应式触发底部状态栏渲染，UI 不直接存储状态 |

# 健康度检查

定期或在重大变更后，执行以下检查：

```text
□ constraints.md 中的不变量是否与代码一致
□ 禁止事项是否被违反
□ 架构状态是否需要更新（代码重构后架构状态可能升级）
□ 术语是否在其他文档中一致使用
□ 是否存在超过 30 天未更新但代码已变更的约束
□ 代码实现与约束描述是否一致
□ 模块定位表（如存在）是否与当前代码结构一致
```

发现不一致时，优先更新知识库，再继续开发。
