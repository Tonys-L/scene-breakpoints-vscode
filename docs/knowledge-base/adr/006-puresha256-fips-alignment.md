# ADR-006: pureSha256 转写偏差修复——对齐上游素数筛上限 313 还原标准 SHA-256

## 状态

Accepted (2026-10-07)

## 背景

`pureSha256`（`src/domain/models/agentRuleAsset.ts`）为领域层零依赖纯 TS SHA-256 实现，逐行同构改编自公版纯 JS 实现 [geraintluff/sha256](https://github.com/geraintluff/sha256)。上游素数筛上限为 `i < 313`，本项目转写时误写为 `i < 300`，导致复合数 **300**（= 2³×5²）与 **301**（= 7×43）逃逸筛网（其最小素因子标记循环分别止于 298/294），被误判为第 63、64 个素数；K 常量 k[62]/k[63] 取 cbrt(300)/cbrt(301) 而非标准 cbrt(307)/cbrt(311)，输出与标准 SHA-256 (FIPS 180-4) 不逐字节一致。

直接后果是官方 Skill 史表为**混算法产物**：

- 1.0.3 键登记于 pre-DDD 时代（node:crypto 标准实现），是标准 SHA-256 指纹；
- 1.0.8 键登记于 DDD 重构后（buggy pureSha256）；
- 任何 `node:crypto` 交叉验证尝试必然失败，指纹语义只能"项目内自洽"，无法外部审计。

## 方案选项

### 选项 A：保持项目内自洽，不修复

史表与运行时同管线生成，互为一致即安全。但永久偏离标准、阻断第三方交叉验证，违背"算法优先成熟第三方实现"工程纪律（自研仅限零依赖硬约束场景，且此处自研已实证存在转写缺陷），且"100% 宿主无关标准 SHA-256"的注释名实不符。

### 选项 B：经 Hasher 端口注入 node:crypto 替换

需在领域层引入 Node API，违反"领域层严禁依赖宿主 API 或外部 SDK"架构约束，丧失宿主无关性。

### 选项 C：引入 @noble/hashes 第三方库

成熟且经审计，但引入项目唯一运行时依赖，违背"零外部生产运行时依赖"构建约束；且仅为替换一个 60 行纯函数，不成比例。

### 选项 D：一行修复 300 → 313（选定）

最小变更还原上游原貌，输出恢复与标准 SHA-256 逐字节一致；史表条目全量经领域管线重生成。

## 决策

采用方案 D。理由：

1. 变更仅一个数值常量，零依赖、零架构影响，实现回归上游公版原貌；
2. 修复后可与 `node:crypto` 逐字节交叉验证（工具实证 4 向量：空串 / `"abc"` / `"hello world"` / fox 全 MATCH），指纹语义从"自洽"升级为"可外部审计"；
3. 指纹一致性的根本契约是**归一化语义**（剥 Frontmatter + CRLF/LF 归一 + trimEnd + trim）而非哈希算法本身——用户侧 `debug-scenes.json` 的断点伴随指纹（Fingerprint VO）为纯文本上下文，不经 pureSha256，存量用户零迁移。

史表考古与重生成（git blob 三层锚定）：

- **1.0.3 键 `f026e09…` 不变**：登记于 pre-DDD 时代（node:crypto 标准实现），修复后经领域管线重算指纹与原键逐字节一致（blob 等价性 `153ca340…` 锚定）；
- **1.0.8 键重登记为 `be86d3a3…`**：修复前 buggy pureSha256 对 1.0.8 blob 的指纹精确命中旧键 `36c8a30…`，证明 blob 身份与旧键混算法属性；
- **1.1.0 键重登记为 `3d042597…`**：修复后管线生成；1.1.0 发布定稿前 SKILL.md 增补"平台护栏写入被拒兜底"节（Platform Write Guard），键随正文最终态重算（`6e7ba206…` 为中间态，未发布已废弃）。

## 影响

- **破坏性变更面：零**。断点伴随指纹为纯文本上下文不经 pureSha256；唯一消费方为 AI Skill/规则版本生命周期判定（CleanOutdated 识别），史表三键全量覆盖 1.0.3 ~ 1.1.0，存量纯净官方用户的版本识别不受影响。
- **测试强化**：`agent_rule_asset.test.mjs` §9 写入 FIPS 180-4 公开标准向量 4 条 + `node:crypto` 动态交叉验证（含中文 UTF-8 经 `computeFingerprint` 的 latin1 字节流编码路径）；守卫测试 `gen_skill_fingerprint.test.mjs` 锚定"当前正文指纹必须已登记史表最新版"。
- **禁止事项强化**：史表指纹与一切版本判定输入必须统一经 `AgentRuleAsset.computeFingerprint()` 生成，严禁 `node:crypto` 直算（防止绕过归一化语义契约）；该警示固化于史表注释。
- **知识库联动**：lessons §6.1 修复记录、INV-013 名实相符（标准 SHA-256）、CHANGELOG [1.1.0] Fixed 双语追加。
