# ADR-001: 基于三行伴随指纹与双向滑动窗口实现代码行号自愈

## 状态
Accepted

## 背景
在团队多人协作或分支切换时，代码发生变动（新增注释、重构、Git Pull），导致 `.vscode/debug-scenes.json` 中保存的绝对行号（例如 line 45）发生上下偏移。如果不进行校准，断点就会打在错误的代码行或空行上，严重损害开发者的调试信任。

## 方案选项

### 选项 A：完整 AST 语法树匹配
- **优点**：准确率理论上最高。
- **缺点**：需要引入 Babel / TypeScript 庞大的编译器运行时依赖，单文件打包体积暴增几十倍；且对 Python、Go、Rust、C++ 等多语言支持成本极大。

### 选项 B：单行文本精确比对
- **优点**：实现极其轻量。
- **缺点**：在多处高频重复行（例如 `return;`、`break;`、`if (!user) return;`）时极易发生严重误判。

### 选项 C：全维上下文指纹 (保留缩进+作用域) + 交替辐射动态打分 (本方案)
- **优点**：
  1. 零外部重型依赖，跨语言通用；
  2. 代码内容指纹与缩进彻底解耦：纯代码剥离首尾空白且中间压缩单空格；缩进独立打分并引入 2:1/1:2 整倍数弹性容错，完美免疫全局 2 空格 ↔ 4 空格重构、Tab/空格互转与 Prettier 格式化；
  3. 采用向下优先的双向交替辐射滑动（+1, -1, +2, -2, ...），更符合代码增补下移规律；
  4. 引入函数作用域轻量正则回溯锚点 (`scopeAnchor`)，配合 `score >= 5` 按需延迟计算与单次 Map 局部缓存，彻底根除 $O(n^2)$ 正则匹配造成的卡顿隐患；
  5. 软容错上下文硬门禁（Context Guard）与词法单元权重比对，仅在至少一行上下文精准命中的前提下才容许轻度重构自愈，彻底杜绝 `return true` 误判为 `return false`；
  6. 动态满分比率阈值（$\ge 68\%$），自适应首行与末行缺失场景。
- **缺点**：当大面积彻底删除重构时安全回退至原行号。

## 决策
选择 **选项 C**。实现于 `src/healingAdapter.ts`。

## 影响
1. 断点数据模型增加 `contextSnippet.scopeAnchor` 与 `indent`；
2. 彻底解决全局 2/4 空格缩进重构失效、格式化空格敏感、无序扫描浪费、作用域循环回溯卡顿、软容错高估误判和首行越界等全部边界隐患；
3. 算法 100 次批量自愈耗时稳定在 1ms 级别，达到毫秒级工业级水准。
