# ADR-004: 建立架构防摇摆与深浅模块裁决工程规范

## 状态
Accepted

## 背景
在基于 AI 的持续重构与架构演化过程中，无历史记忆的静态架构分析器或不同轮次的 AI 模型容易陷入经典的“架构摆锤效应”（Architectural Thrashing / Churn）：
- **摆向一端（过度合并）**：扫描器看到小模块或委托转发，误将其判定为“浅模块 / 胶水层”，提议将 `ActiveBreakpointIndex`、`BreakpointManager`、`SceneStateManager` 甚至领域实体重新合并回庞大的 `SceneManager` 上帝对象；
- **摆向另一端（过度拆分）**：下一轮分析又指出上帝对象违反单一职责原则（SRP）、文件行数超标或圈复杂度膨胀，提议将其重新拆散。

如果缺乏一套**业务无关、正交客观的工程裁决标准**，AI 助手将陷入无休止的“拆了合、合了拆”的负效代码震荡。

## 方案选项

### 选项 A：依赖单次分析提示词主观约束
- **优点**：无需编写固定规范。
- **缺点**：不可复现，AI 在每次开启新会话或上下文压缩后依然会重复提出相反的重构建议。

### 选项 B：建立业务无关的“防架构摇摆五步裁决协议”并固化为硬门禁 (本方案)
- **优点**：
  1. **客观物理判据**：通过变更节拍、依赖框架、实体主权、共变性与删除测试 5 个正交维度，为任何重构提议提供无可辩驳的判决逻辑；
  2. **终结 AI 摇摆**：对伪中间人（Hollow Middleman）精准修剪，对正当深浅分立实施刚性保护；
  3. **普适且可推广**：无论未来新增何种业务，均可套用此判据裁决模块该合该分。
- **缺点**：需要在重构前执行自检判定。

## 决策
选择 **选项 B**。制定普适的 5 步决策协议，并在 `docs/knowledge-base/constraints.md` 中固化为硬约束：

### 防架构摇摆五步裁决协议 (The 5-Step Anti-Churn Protocol)

1. **测试一：变更节拍与性能热点隔离测试 (Cadence & Hotpath Isolation Test)**
   - **判据**：两部分代码的执行频次与性能要求是否处于不同量级？
   - **规则**：若模块 A（如 `ActiveBreakpointIndex`）处于高频只读热点（每毫秒被 InlayHints / DAP 命中查询），而模块 B（如 `SceneManager`）属于低频写事务（用户点击导入导出、持久化磁盘写盘），**严禁物理合并**。内存投影与持久化编排必须物理隔离。

2. **测试二：依赖层级与框架边界测试 (Dependency Level & Framework Boundary Test)**
   - **判据**：两部分代码是否处于不同的依赖层级或受不同的外部生态约束？
   - **规则**：直接依赖外部平台 API / 宿主协议（如 Node `fs`、VS Code API、DAP 协议）的基础设施代码，严禁为了“减少文件”而与纯领域计算、纯应用编排或纯 UI 展示逻辑混编。

3. **测试三：充血实体主权与防上帝对象测试 (Sovereign Entity vs. God Object Test)**
   - **判据**：合并是否剥夺了领域实体/聚合根的自治业务行为？
   - **规则**：领域实体与聚合根（如 `Scene`、`Breakpoint`、`SceneCatalog`）天然自治，拥有数据与状态变更方法。应用层 Manager / Service 专职编排用例生命周期，**严禁将实体的业务方法掏空并摊平到外层 Manager 中**。

4. **测试四：共变性与删除测试 (Co-variation & Deletion Test)**
   - **判据**：两个模块在业务演进时是否总是一同修改？若合并/删除一个模块，是真正消除了复杂度，还是仅仅把复杂度平移？
   - **规则**：若合并导致单文件行数逼近/超过硬门禁（GR-013: 400 行）或导致圈复杂度急剧升高（触发 CRAP 立方惩罚），则**拆分完全正当**，严禁逆向合体。

5. **测试五：伪中间人与正当门面判定 (Middleman vs. Legitimate Facade Test)**
   - **判据**：该方法/模块是为一组复杂子系统提供高阶降噪抽象，还是纯粹 1:1 转发给另一个已公开单例？
   - **规则**：真正的**深模块门面**予以保留；无任何参数转换、防御校验或逻辑聚合的**纯空壳透传桩（Hollow Stubs）坚决剔除**，调用方直接访问真实单例。

## 影响
1. 规范了未来所有重构与深模块演化的审查流程，彻底杜绝无意义的模块合拆拉锯；
2. 清理了 `src/application/sceneStateManager.ts` 中的 5 个无用透传桩；
3. 根除了 `src/ui/commands/treeCommands.ts` 中的最后违规 `fs` 导入与多处代码重复；
4. 确保工程在 Clean Architecture、高内聚低耦合与极限简洁之间达成稳态平衡。
